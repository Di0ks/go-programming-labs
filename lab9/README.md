# Лабораторная работа 9

В этой лабораторной работе был создан клиент для REST API сервера, созданного в прошлой лабораторной работе. Приложение
представляет собой консольный интерфейс с REPL-подобной средой. Были реализованы CRUD операции, обработка ответов и
ошибок, форматированный вывод, авторизация пользователей и поддержка нескольких сессий (с отправкой токена сессии
на сервер).

## Задания

Задания лаборатной работы:
1. Создание клиентской программы:
  - Напишите клиентское приложение, которое отправляет запросы на ваш сервер.
  - Реализуйте простое меню с возможностью выполнения CRUD операций.
2. Обработка ответов:
  - Реализуйте механизм обработки ответов и ошибок.
  - Добавьте функции для форматирования и вывода полученных данных на экран.
3. Интерфейс пользователя:
  - Разработайте консольный интерфейс с меню для пользователя.
  - Включите возможность добавления, удаления и обновления информации о пользователях.
4. Авторизация пользователя:
  - Добавьте поддержку авторизации пользователя.
  - Клиент должен сохранять токен сессии и передавать его в заголовках последующих запросов.
5. Поддержка нескольких клиентов:
  - Модифицируйте клиентскую часть так, чтобы несколько клиентов могли одновременно взаимодействовать с сервером.
6. Тестирование и отладка:
  - Проведите тестирование взаимодействия клиента и сервера.
  - Проверьте работу всех маршрутов и функций.

## Запуск

Для запуска приложения необходимо находиться в директории лаборатной работы и выполнить команду:
```bash
go run .
```
Кроме того, нужно чтобы был запущен REST API сервер из предыдущей работы (смотрите [README.md](../lab8/README.md) предыдущей работы).

## Описание приложения

Запустите приложение из каталога `lab9` командой `go run .`. После ввода адреса сервера появится меню авторизации:

- `reg` — зарегистрировать пользователя;
- `login` — войти;
- `help` — показать доступные команды;
- `quit` — завершить приложение.

При регистрации имя и пароль запрашиваются интерактивно, пароль нужно повторить. Имя обрезается по краям и должно быть уникальным с учётом регистра; пароль не может быть пустым. Пароль хранится только как bcrypt-хэш.

Учётные записи сохраняются в `users.json` в текущем каталоге. Файл создаётся при первой успешной регистрации. Другой путь можно задать переменной `LAB9_USERS_FILE`. Формат файла:

```json
{
  "users": [
    {
      "username": "alice",
      "password_hash": "bcrypt-хэш"
    }
  ]
}
```

Файл создаётся с правами только для владельца и исключён из Git. Шаблон структуры находится в `users.json.example`.

После входа доступны команды CRUD: `list`, `add`, `edit <id>`, `del <id>`. Несколько сессий хранятся только в памяти процесса, а операции выполняются последовательно:

- `login` — добавить сессию существующего пользователя;
- `reg` — зарегистрировать пользователя и создать для него сессию;
- `sessions` — показать имена сохранённых сессий (`*` отмечает активную);
- `switch <имя>` — сделать активной уже сохранённую сессию;
- `logout` — завершить только активную сессию; остальные останутся сохранёнными;
- `help`, `quit` — справка и завершение приложения.

Если сессии нет, `login`, `reg`, `sessions`, `switch`, `help` и `quit` остаются доступны. При успешном `login` или `reg` первая сессия становится активной; если активная сессия уже была, она остаётся текущей до команды `switch`. Prompt показывает имя активного пользователя, не раскрывая токен.

После успешного входа клиент создаёт случайный токен сессии и передаёт его API в заголовке `Authorization: Bearer <token>`. Токен хранится только в памяти процесса. На данном этапе сервер его не проверяет, поэтому локальная проверка не является серверной защитой API.
