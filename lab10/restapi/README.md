# REST API

REST API сервер на Go для хранения и изменения пользовательских записей в PostgreSQL. SQL-схема находится в `users.sql`; там создаются таблицы `users` и `sessions`. Пароли регистрируемых пользователей хранятся в виде bcrypt-хэшей, а новые учётные записи получают роль `user`.

## Аутентификация и сессии

Регистрация и вход (`POST /auth/register`, `POST /auth/login`) являются публичными маршрутами, необходимыми для создания учётной записи и сессии. Остальные маршруты данных требуют действительную серверную сессию. Сервер генерирует случайный идентификатор сессии и CSRF-токен; в таблице `sessions` хранится SHA-256-хэш идентификатора, ссылка на пользователя, CSRF-токен и срок действия. Сессия действует 24 часа.

Идентификатор передаётся клиенту в cookie `session_id` с атрибутами `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. `GET /auth/csrf` возвращает synchronizer-токен для текущей сессии. Для выхода и изменяющих запросов требуется передать его в `X-CSRF-Token`; сервер сравнивает токен с сохранённым постоянным по времени сравнением. `POST /auth/logout` удаляет сессию и очищает cookie.

## Маршруты и роли

| Маршрут | Доступ | Назначение |
| --- | --- | --- |
| `POST /auth/register` | Публичный | Создать пользователя и начать сессию |
| `POST /auth/login` | Публичный | Проверить пароль и начать сессию |
| `GET /auth/csrf` | Сессия | Получить CSRF-токен |
| `POST /auth/logout` | Сессия + CSRF | Завершить сессию |
| `GET /users`, `GET /users/{id}` | `user` и `admin` | Читать записи |
| `POST /users`, `PUT /users/{id}`, `DELETE /users/{id}` | `admin` + CSRF | Создавать, изменять и удалять записи |
| `GET /admin/info` | `admin` | Получить сведения о Go-сервере и подключении к БД |

Роль берётся из базы при аутентификации сессии. Регистрация не позволяет назначить себе `admin`.

## Предыдущая JWT-версия

В предыдущей реализации сервер выдавал подписанный JWT после входа или регистрации. Клиент передавал его в `Authorization: Bearer ...`, а сервер проверял подпись, срок действия и роль из claims. Эта версия сохранена в коммите `bf8f67a`. Текущая реализация использует серверные сессии и cookie вместо JWT.
