# REST API пользователей

Сервис управляет пользователями в PostgreSQL и предоставляет HTTP API по адресу `http://127.0.0.1:8080`.

## Запуск

Перед запуском должна существовать база данных `goserv`, а пользователь `postgres` должен иметь к ней доступ. Таблица и последовательность создаются при старте сервиса.

```sh
cd lab8
go run .
```

Параметры подключения по умолчанию заданы в `NewDbConfig`: `127.0.0.1:5432`, база `goserv`, пользователь `postgres`.

## Формат пользователя

Поля JSON:

| Поле | Тип | Правила |
| --- | --- | --- |
| `name` | string | Обязательно при создании; после удаления пробелов не должно быть пустым |
| `age` | integer | Обязательно при создании; диапазон от 0 до 150 включительно |
| `email` | string | Обязательно при создании; должен быть корректным адресом электронной почты |
| `comment` | string или `null` | Необязательное поле |
| `phone` | string или `null` | Необязательное поле; строка должна содержать от 7 до 15 цифр, допускаются `+` в начале, пробелы, дефисы, скобки и точки |

Неизвестные поля в JSON отклоняются. Идентификатор задаётся сервером и не принимается в теле запроса.

## Маршруты

| Метод и путь | Назначение | Успешный ответ |
| --- | --- | --- |
| `GET /users` | Список пользователей с пагинацией и фильтрами | `200 OK`, JSON-объект, ключи — ID пользователей |
| `GET /users/{id}` | Получить пользователя | `200 OK`, JSON-объект пользователя |
| `POST /users` | Создать пользователя | `200 OK`, пустое тело |
| `PUT /users/{id}` | Обновить переданные поля пользователя | `200 OK`, пустое тело |
| `DELETE /users/{id}` | Удалить пользователя | `200 OK`, пустое тело |

В JSON отдельного пользователя поле `id` не возвращается. В списке ID используется как ключ объекта.

### Получить список: `GET /users`

Параметры запроса необязательны:

| Параметр | Значение |
| --- | --- |
| `limit` | Размер страницы, по умолчанию `20`; допустимо от `1` до `100` |
| `offset` | Число пропускаемых записей, по умолчанию `0`; должно быть неотрицательным целым числом |
| `name` | Поиск по подстроке имени без учёта регистра |
| `email` | Поиск по подстроке email без учёта регистра |
| `phone` | Поиск по подстроке телефона без учёта регистра |
| `min_age` | Минимальный возраст, включительно; от `0` до `150` |
| `max_age` | Максимальный возраст, включительно; от `0` до `150` |

Фильтры объединяются условием AND. Пустые строковые фильтры игнорируются. `min_age` не может превышать `max_age`. Результаты упорядочены по ID по возрастанию.

В ответе передаются заголовки:

- `X-Total-Count` — число записей, подходящих под фильтры, до применения пагинации;
- `X-Limit` — применённый размер страницы;
- `X-Offset` — применённое смещение.

Пример:

```sh
curl 'http://127.0.0.1:8080/users?name=ann&min_age=18&max_age=40&limit=10&offset=0'
```

Пример ответа:

```json
{
  "12": {
    "name": "Anna Smith",
    "age": 28,
    "comment": null,
    "email": "anna@example.com",
    "phone": "+1234567890"
  }
}
```

### Получить пользователя: `GET /users/{id}`

`id` должен быть положительным целым числом.

```sh
curl http://127.0.0.1:8080/users/12
```

Если пользователь не найден, API возвращает `404 Not Found`.

### Создать пользователя: `POST /users`

Передайте JSON с обязательными полями `name`, `age`, `email` и необязательными `comment`, `phone`:

```sh
curl -X POST http://127.0.0.1:8080/users \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Anna Smith",
    "age": 28,
    "email": "anna@example.com",
    "comment": "Новый пользователь",
    "phone": "+1234567890"
  }'
```

При успешном создании тело ответа пустое. Чтобы получить созданную запись, используйте `GET /users` с подходящим фильтром.

### Обновить пользователя: `PUT /users/{id}`

Тело может содержать любое подмножество полей. Неуказанные поля останутся без изменений. Переданные `name`, `age`, `email` и `phone` проходят ту же валидацию, что и при создании. Передача `null` для `comment` или `phone` очищает соответствующее поле. Пустой объект `{}` не меняет запись, но проверяет существование пользователя.

```sh
curl -X PUT http://127.0.0.1:8080/users/12 \
  -H 'Content-Type: application/json' \
  -d '{"age": 29, "comment": null}'
```

### Удалить пользователя: `DELETE /users/{id}`

```sh
curl -X DELETE http://127.0.0.1:8080/users/12
```

## Ошибки

Ответы об ошибках имеют JSON-формат:

```json
{
  "error": "Возраст должен быть от 0 до 150 лет",
  "field": "age"
}
```

Поле `field` опускается, если ошибка не относится к конкретному полю.

| Код | Причина |
| --- | --- |
| `400 Bad Request` | Некорректный ID, JSON или параметры списка |
| `404 Not Found` | Пользователь с указанным ID не найден |
| `422 Unprocessable Entity` | JSON корректен, но значение поля не прошло валидацию |
| `500 Internal Server Error` | Ошибка при выполнении запроса к базе данных |
